Privacy & Google authorization

Privacy Policy — Ary Rongel Position Logger

Last updated: October 22, 2026.

This policy describes how Ary Rongel Position Logger processes navigation data and uses Google authorization. It also describes this public documentation website.

1. Purpose of the application

Ary Rongel Position Logger is a Windows application used to record vessel-position information for the Navio de Apoio Oceanográfico Ary Rongel, callsign PWAR. It keeps a local daily history and, when enabled and authorized by the operator, stores GeoJSON files in that operator’s Google Drive.

2. Google user data accessed

The application uses Google OAuth 2.0 and requests only this Google Drive scope:

https://www.googleapis.com/auth/drive.file

This scope allows access to files created or opened by the application within the user’s authorization. It does not grant unrestricted access to all files in the user’s Google Drive.

The application uses metadata for its working folders and files, such as names, IDs, sizes and links. When testing the Drive connection, it also reads the authorized account’s display name and email address to identify the connected account to the operator.

3. How Google data is used

Google authorization is used only to connect the authorized account, create or locate the application’s folders, upload its daily GeoJSON files and backup snapshots, and track upload results. The working folder is named CATS - Ary Rongel, with Diarios and Backups subfolders by default.

The current implementation creates new files and checks for an existing file before uploading. It does not overwrite published daily files or change their sharing permissions. Account information is used to show the connected account in the application.

4. Data generated by the application

The application processes latitude, longitude, UTC timestamps, speed, true course, heading, vessel identification and callsign when available from the configured navigation source.

Daily GeoJSON files currently contain position coordinates, the original UTC fix timestamp, vessel name, callsign, speed and heading. True course may be used as a heading fallback. Local operational records also include file counts, upload metadata, errors and alerts.

5. Storage

Position files are stored locally on the operational computer. When Drive uploads are enabled, closed daily files and backup snapshots are also stored in the Google Drive account authorized by the operator. Upload status and related metadata are stored in a local SQLite database.

The application does not send position files or Google authorization data to this documentation website. Google processes files stored in Drive under the terms and privacy policies applicable to the authorized account.

6. OAuth credentials

OAuth tokens are stored locally on the operational computer. OAuth tokens are protected using Windows Data Protection API (DPAPI). This protection is tied to the Windows user account. The Desktop OAuth client configuration is also kept in the local application data directory; it is not protected by DPAPI.

For Linux development, the token is stored in a local file with user-only permissions instead of Windows DPAPI. Tokens and client secrets are not intended for inclusion in the Git repository, this website or application logs.

7. Sharing

The application does not sell Google user data. Files created by the application may be shared by the authorized operator with organizations or systems involved in the vessel-position reporting workflow, including CATS-related workflows where arranged by the responsible organization.

The operator or administrator controls sharing through Google Drive. Uploading a file does not automatically make it public. This website does not establish an official affiliation, endorsement or sponsorship by COMNAP.

8. Retention and removal

Position files and backup snapshots remain on the operational computer and, when uploaded, in Google Drive until removed by the operator or handled under the organization’s operational procedures. The application does not automatically delete historical position files. Diagnostic logs rotate locally.

To remove stored files or authorization data, the operator must use the appropriate local computer and Google Drive controls. Copies already shared with other recipients are subject to those recipients’ procedures.

9. Revoking access

You can revoke the application’s access from your Google Account connections and security settings. After revocation, the application cannot continue authorized Drive operations unless you reconnect it.

Revoking access does not automatically delete existing files from Google Drive or the operational computer. Local NMEA recording can continue independently of Google Drive.

10. This documentation website

These pages do not set cookies, use analytics, run tracking scripts or embed external libraries. GitHub Pages hosts the website and may process connection information under the GitHub Privacy Statement. External links take you to services governed by their own policies.

11. Contact

For questions about this policy or the application’s handling of data, contact vitortcc01@gmail.com.
